# Linear + GitHub PR Integration

Semi-automated workflow to create a GitHub Pull Request linked to a Linear issue.

## Workflow Steps

### 1. Gather Context

```bash
# Check Linear issue details
gh api graphql -f query='
  query {
    issue(id: "<ISSUE-ID>") {
      title
      description
      state
      labels
    }
  }
'

# Check git status
git status
git diff main...HEAD
git log main...HEAD --oneline
```

### 2. Generate PR Description

Agent analyzes:

- Linear issue title and description
- All commits in current branch
- File changes (git diff)
- SPARC documentation in `/docs/features/`
- Test coverage reports

Creates PR description with:

```markdown
## Summary

<Feature overview from Linear issue>

## Changes

- List of key changes from commits and diffs

## Testing

- ✅ Rust tests: X/X passing (Y% coverage)
- ✅ Frontend tests: X/X passing (Y% coverage)
- ✅ E2E tests: X/X passing

## Related Issues

Closes <LINEAR-ISSUE-ID>

## Architecture

See `/docs/architecture/<feature>-design.md`

---

Generated by claude-flow agent: PR Manager
```

### 3. Create Draft PR

```bash
# Create branch if needed
git checkout -b feature/<issue-id>-<slug>

# Stage and commit if there are uncommitted changes
git add .
git commit -m "feat: <feature description>

Closes <LINEAR-ISSUE-ID>"

# Push to remote
git push -u origin feature/<issue-id>-<slug>

# Create draft PR
gh pr create \
  --draft \
  --title "<Linear Issue Title>" \
  --body "<Generated Description>" \
  --label "rustalk,<platform-labels>" \
  --base main
```

### 4. Link to Linear

PR description includes `Closes <LINEAR-ISSUE-ID>` which:

- GitHub-Linear integration auto-links PR to issue
- Linear issue status updates to "In Review"
- On PR merge, Linear issue auto-closes

## Agent Coordination

```javascript
// Single message workflow
Task("PR Manager Agent", "Create PR for Linear issue <ISSUE-ID>", "pr-manager")

// PR Manager uses memory for context
mcp__claude-flow__memory_usage {
  action: "retrieve",
  key: "rustalk/features/<feature-slug>/spec",
  namespace: "rustalk"
}

// Store PR URL
mcp__claude-flow__memory_usage {
  action: "store",
  key: "rustalk/prs/<issue-id>",
  namespace: "rustalk",
  value: JSON.stringify({
    pr_number: 42,
    url: "https://github.com/owner/rustalk/pull/42",
    linear_issue: "<ISSUE-ID>",
    status: "draft"
  })
}
```

## Example Usage

```bash
# Create PR for Linear issue
npx claude-flow@alpha command rustalk/linear-pr --issue "RUST-123"

# With explicit feature name
npx claude-flow@alpha command rustalk/linear-pr --issue "RUST-123" --feature "SIP Registration"
```

## Human Review Checklist

After agent creates draft PR, human reviewer should:

1. **Review Code Quality**:
   - [ ] Code follows Rust/TypeScript style guidelines
   - [ ] No hardcoded secrets or credentials
   - [ ] Proper error handling
   - [ ] Adequate test coverage

2. **Review Tests**:
   - [ ] All tests passing in CI
   - [ ] Coverage meets requirements (85% Rust, 80% Frontend)
   - [ ] E2E tests cover critical paths

3. **Review Documentation**:
   - [ ] Architecture docs updated
   - [ ] API documentation generated
   - [ ] Comments explain complex logic

4. **Approve and Merge**:
   - [ ] Mark PR as "Ready for review"
   - [ ] Request additional reviews if needed
   - [ ] Merge when all checks pass
   - [ ] Linear issue auto-closes

## Linear Integration Setup

Ensure GitHub-Linear integration is configured:

```bash
# In Linear settings
1. Go to Settings → Integrations → GitHub
2. Connect your GitHub repository
3. Enable "Auto-close issues on PR merge"
4. Configure label syncing (optional)
```

## Next Steps

After PR is created:

1. Human reviews draft PR
2. Agent can address review feedback via additional commits
3. Human approves and merges
4. Linear issue auto-closes
5. Branch auto-deletes (if configured)
